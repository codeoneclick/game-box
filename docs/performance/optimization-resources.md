| Q01 | Job workers wait on condition-variable work generations rather than 100 ms polling or spinning on main-only work. Queue-root claims prevent simultaneous main/background traversal. Callback/status updates are synchronized and exactly once; dependency completion is required before advancing. ## Commands and observed results

All standalone probes compile actual production implementation code. Scheduler/XML probes replace platform or asset class declarations only where necessary to isolate non-render work; the FBX probe uses the real resource/sequence/serializer sources and ufbx. These are focused standalone checks, not a newly claimed engine unit-test suite.

- `./gbScripts/check-core-scheduling.ps1`: initial pre-fix run failed background wakeup due to 100 ms polling; post-fix pass. Blocked-main worker CPU measured 0 ms over a 180 ms wait in the check. Deterministic stale nested leaf regression plus 100 concurrent iterations pass.
- `./gbScripts/check-shader-precompile.ps1`: pass, exact SPIR-V/cache-key/reflection/CPU-only preparation checks. An initial probe compile needed the missing shim `f32` alias; production code was not changed for that test setup error.
- `./gbScripts/check-configuration-cache.ps1`: pass. Initial fallback fixture used free XML text accepted by this pugixml version; corrected fixture to a malformed tag, then fallback/cache tests passed.
- `./gbScripts/check-fbx-stream-frames.ps1`: pass, idle 91 frames and walk 25 frames, every sampled bone pose matches direct reference exactly.

Full Windows build, demo capture and backend measurements are root-owned and must be recorded separately. No independent Metal/OpenGL runtime verification was performed here.
