# ECS and character optimization implementation

2026-10-10. IDs E01-E22 follow the source-of-truth catalog in `CORE_PERFORMANCE_AUDIT.md`. Changes were made on top of the existing dirty working tree. Final Woodsman assets, Mixamo retarget/grounding math, exact animation cadence, 200 residents, terrace constraints, feeder phase order and next-tick membership remain the intended contracts. No animation LOD, time quantization, reduced update frequency, GPU readback, or physics timestep migration was introduced.

## Implemented and investigated

| ID | Result and source evidence | Remaining scope |
|---|---|---|
| E01 | `ces_animation_3d_system.{h,cpp}` memoizes exact TRS samples and composed local matrices for consecutive instances with identical frame pointers/revisions/interpolation/bone count. Every instance still updates its blend frame, skeleton bind multiplication and final palette every tick. Layered and crossfade animations bypass this reuse. Public frame TRS updates and copy assignment advance a monotonic revision; cache keys validate both frames, preserving callback-driven edits. | Arbitrary multi-pose batching/instanced crowd storage requires renderer integration; animation LOD is intentionally excluded by image-quality constraint. |
| E02 | `ces_skeleton_3d_component::get_root_bones()` returns a const reference, removing per-frame set-node allocation/copy. | None for the reported copy. |
| E03 | Additional-layer snapshot and updated-state scratch reuse thread-local vector capacity. The snapshot is retained because animation-ended callbacks may mutate mixer state. | Scratch assumes the existing non-reentrant feed execution; no asynchronous animation evaluation was introduced. |
| E04 | `animation_3d_mask` indexes first-added weights by name; animation mixer resolves one weight instead of three per bone/layer. Duplicate-name first-match weight behavior remains intact. | Compiled bone-index masks and fully hoisted layer frames can further reduce string/hash traffic. |
| E05 | Final skeleton-to-mixer palette uses dense `std::copy` without a second per-bone shared-pointer lookup. `resident_bone_uniforms` initializes inactive identity slots once and only resets a tail when active bone count shrinks. | Backend palette upload and draw batching are separate renderer work. Storage aliasing was avoided to preserve public pointer/lifetime contracts. |
| E06 | Grounding remains sparse CPU contact evaluation with unchanged math/cadence; E01/E05 reduce its upstream palette cost. | Skipping visible/offscreen grounding or GPU grounding would alter contracts or require readback, so those proposals were not implemented. |
| E07 | Resident start compares position/yaw before component setters; unchanged idle transforms no longer rebuild Euler matrices or invalidate caches. | Generic component setters retain original initialization semantics. |
| E08 | Internal transform traversal borrows the ordered child vector; absolute transformation update returns early for an identical parent matrix. | Whole-scene dirty scheduling and replacing immediate property propagation would change timing; retained. |
| E09 | Feeder drains changes, records each entity's final erase event, erases once per query and appends surviving events in original final order. Existing duplicate-added behavior, expiry cleanup on changed/remove events, phase order and next-tick application are preserved. | Hash scratch still allocates under structural churn; a persistent indexed ECS store is a larger architecture change. |
| E10 | Removed the >2048 reference branch that repeatedly flushed logs/cleaned live entries and skipped query processing. Large live queries now process normally. | None for the capacity-driven diagnostic/skip behavior. |
| E11 | Query enumeration locks each weak entity once, rather than checking expiry then locking. | Typed dense ECS storage, removal of all shared ownership, and fixed 255-slot storage migration remain architecture work. |
| E12 | Skeleton and mixer palettes are owned by vectors; existing raw palette getters point to that storage. Skeleton setup rebuilds bone ownership/index, so repeated setup has a defined new rig. Vector destruction frees storage. | No allocator leak profiler was run; ownership fix is source-evidenced. |
| E13 | Bone creation console flushes removed; raw rig data is borrowed and dense bone index reserves capacity. | Shared immutable inverse-bind rigs would require changing mutable bone APIs; retained. |
| E14 | Fabricator retarget/cache preparation belongs to resource owner and was forwarded to root/resource agent. | This agent did not edit fabricator or claim this row implemented. |
| E15 | Population residents share immutable, grid-ordered reachable points by connected region. The first BFS marks region cells for subsequent residents; RNG/destination order is unchanged. Standalone/custom state retains its legacy `reachable` vector fallback. | Temporary per-cell shared-reference index exists only during population construction. |
| E16 | BFS uses per-thread generation-stamped visited/parent scratch and vector FIFO, avoiding full-grid parent clearing and repeated queue allocations. Four-neighbor visit order and returned path are unchanged. | A*, asynchronous path requests and request budgeting change chosen paths/timing; deliberately not introduced. |
| E17 | The same 16 footprint offsets are computed once, preserving the original floating-point formulas, exact contour tests and clearance. | Conservative whole-footprint cell certification would need stronger geometric proof. Existing per-point solid-cell shortcut remains. |
| E18 | Touch hit testing borrows ordered DFS children instead of allocating a child snapshot per visited node/event. | Spatial index/query order needs a maintained draw-priority contract; full DFS remains. Events are not coalesced or dropped. |
| E19 | One 3D unprojected ray is cached per event; all 3D candidates share it. | Callback lists stay snapshots: callbacks can modify registration, and replacing them with borrowed traversal risks invalidation/changed dispatch. |
| E20 | Borrowed transform traversal and parent-equality cache reduce physics descendant overhead through E08. Shape setup borrows shape/vertex data. | Sleeping-body skip is not automatically safe for explicit transforms/teleports or callers relying on synchronization. Authoritative body sync remains. |
| E21 | Inspected fixed-step-per-render behavior and retained it. | Changing to an accumulator affects racing speed and update ordering; requires explicit gameplay timing acceptance and separate characterization. GPU Box2D is a new solver architecture. |
| E22 | Contact ignore list and shape-parameter getters return const references; core consumers borrow them. | Ignore-list searches remain linear for small lists; collision filter migration alters public collision behavior. |
