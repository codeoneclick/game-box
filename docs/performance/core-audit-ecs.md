# Core audit: ECS, transforms, animation, navigation, physics and input

Read-only audit completed against the current dirty working tree on 2026-10-10. No engine/application files changed; no builds/runtime measurements performed. All timing priorities below are **static candidates**, not proven bottlenecks. The source-level allocations/copies and missing deallocation are directly evidenced.

Current frame path: `game_transition.cpp:165–180` registers touch order 0, physics order 1, animation order 3; resident system order 6 (`gbDemo/sources/ces_island_resident_system.cpp:17`). Feeder executes every system’s start phase before any feed phase. Thus resident navigation/transforms run in start, core animation evaluates palettes in feed, resident grounding/uniform preparation follows in feed.

Important exclusions/caveats:

- The dirty current code **already fixes integer bone lookup** with `m_bones_by_id` (`ces_skeleton_3d_component.cpp:88`). The old O(B²) recursive lookup is not the normal current frame path; name lookup and legacy unregistered direct bone attachments still recurse.
- Resident shader does vertex deformation on GPU (`gbBundle/Shaders/shader_island_resident.vert:5`). CPU evaluates animation palettes and sparse grounding contacts. A compute skinning pass only pays if the deformed mesh is reused across sufficient passes; the resident material currently names one `ws.base` pass, so compute adds buffer writes/barriers without an obvious reuse win.
- Foot contacts are collected once/shared at `island_resident_demo.cpp:72–94`; no normal per-character full-mesh grounding scan.
- `GB_RESIDENT_DEBUG` enables full vertex skin bounds scan and flushed logs at resident system `:86–104`; keep debug disabled during normal benchmarking.
- Feeder diagnostic `GB_PROFILE_SYSTEMS` adds per-system type-name/string map construction each start/feed/end (`ces_systems_feeder.cpp:47–49`), excludes structural-changes and cleanup from named samples, but includes them in total feeder time. Root measurements should account for that overhead.
- No CPU/GPU performance benefit above is measured here; dynamic rankings, exact bone count/contact count, active Box2D population, and runtime allocation traces remain UNKNOWN.
