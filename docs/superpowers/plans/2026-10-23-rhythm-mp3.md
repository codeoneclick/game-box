# Rhythm Ship MP3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Play the three supplied MP3s with verified beat maps, safe track switching and persistent tap calibration.

**Architecture:** Decode bounded immutable PCM in gbSound; keep WinMM/OpenAL output and playback clocks. A demo-owned controller publishes matching song/map/session state on the game loop. Offline analysis supplies beat maps; calibration adjusts input timestamps only.

**Tech Stack:** C++11-compatible application code, existing JsonCpp/UI/ECS, pinned dr_mp3, WinMM/OpenAL, Python 3/NumPy for offline analysis.

**Spec:** `docs/superpowers/specs/2026-10-23-rhythm-mp3-design.md` (approved).

## Global Constraints

- Preserve the existing ocean, sky, gameplay and debug controls.
- No networking, downloads, arbitrary runtime beat detection, new renderer, or second audio/game framework.
- These source assets must retain their original filenames and bytes.
- Audio backend calls remain on the game-loop path.
- Preserve existing per-source exception/RTTI overrides and C++11 compatibility.
- Positive offset means late taps: subtract it exactly once when enqueueing game input. Limit to +/-250 ms.
- Four count-in pulses and 24 measured taps; failed calibration preserves the previous saved value.
- Native Apple/OpenGL/Metal validation remains UNKNOWN on this Windows host.
- Continue native execution in the existing diskoteka checkout, preserving the execution method selected earlier. No merge/push.

## Review Focus

- A valid decoder prefix followed by truncation must produce a diagnostic rather than fabricated map duration (Task 1).
- A restored preferences file containing a non-object, NaN-like text or out-of-range offset must preserve defaults safely (Task 4).
- Repeated track selections and scene shutdown during decoding must neither publish stale audio nor retain detached work (Task 3).
- Debug changes and calibration completion during track loading must not score taps against mismatched epochs (Tasks 3/4).
- Device position-unit changes and 32-bit rollover must not jump time or freeze scoring (Task 1).

### Task 1: Bounded MP3 decoding and format-correct playback

**Files:** New PCM/decoder files; existing transport; `gbScripts/check_rhythm_audio.cpp`, `gbScripts/check-rhythm-audio.ps1`; gbSound projects and registration script.

**Interfaces (namespace gb::al):**
- `RhythmPCM { unsigned sample_rate, channels; std::vector<int16_t> samples; double duration() const; }`, where frame count is samples.size()/channels.
- `bool decode_rhythm_mp3(const std::string&, RhythmPCM&, std::string&)`: output unchanged on failure, max 600 seconds/128 MiB decoded, mono/stereo only. Separate container validity from recoverable MP3 padding; document decoder limitations.
- Add `bool RhythmAudioTransport::start_pcm(std::shared_ptr<const RhythmPCM>, const std::string& label)`; retain `start(const RhythmAudioConfig&)` for metronome checks.
- `RhythmPositionCounter::seconds(uint32_t value, RhythmPositionUnit unit, unsigned rate, unsigned channels)`: track raw rollover in each returned unit before converting; reset/rebase on unit change so elapsed position remains continuous. Values are frames, bytes or milliseconds, never interleaved scalar samples.

- [ ] Write focused checks: 44100-Hz stereo samples represent expected frames/duration; TIME_BYTES uses four bytes/frame; rollover at 2^32 works in every unit; a unit change preserves continuity. Missing, empty, random and deliberately truncated files fail safely; decode all three originals with expected stereo/rate and plausible durations within 0.2 seconds of the analysis report.
- [ ] Run `./gbScripts/check-rhythm-audio.ps1`; capture expected missing-interface failures before implementation.
- [ ] Pin dr_mp3 to an immutable upstream revision, record license/hash, implement decoder in one translation unit, validate bounded allocation and metadata before publishing PCM. Update registration and standalone compile sources.
- [ ] Generalize transport to immutable source PCM, source rate/channels, WinMM format and OpenAL mono/stereo16. Keep source memory alive through stop/reset. Rebase explicit silent fallback; keep direct synchronous OpenAL ownership. Preserve existing generated-click checks.
- [ ] Run the audio checker with real device and forced silent paths; build debug-client to catch owning-module/project errors. Commit only this task's sources/metadata/checks and update execution ledger.

### Task 3: Safe loading, switching and matching publication

- `RhythmShipPlayback::select(size_t)`, `restart(const RhythmTrack&)`, `update()`, `tap(double raw_seconds)`, `bool scoring_active() const`. Own catalog, loader, active PCM/index and weak-safe scene callbacks; use existing shared session/audio/bots objects without replacing their shared identities.
- UI receives callbacks for previous/next track; `set_playback_status(const std::string&)` updates a readable title/loading/fallback label. Input's tap callback receives audio seconds immediately on arrival.

- [ ] Add checks with an injectable decoder: block first request, issue two more, ensure only newest pending generation publishes; destroy during decoding and prove join; repeated R reuses active PCM; loading taps do not score. Establish RED in a focused standalone loader checker.
- [ ] Implement loader and controller. Stop scoring while loading, discard stale results, start matching PCM/map/session together on game loop, clear old pending taps, reset bots/score/time. Audio failure retains selected timeline in labeled silent mode; decode failure publishes metronome with metronome title/map/duration. Reset diagnostic log epoch on restart.
- [ ] Add previous/next controls and default Audioera selection. Preserve debug restart/map offset edits via controller, existing R/F1/key-repeat suppression, force-silent mode and environment appearance. Guard callback lifetimes on teardown.
- [ ] Run focused checks and debug build. Exercise each song, rapid switching/loading, R and bad-file fallback; capture title, rate/channels, duration, map ID and generation in opt-in diagnostics. Commit this integrated controller/UI slice.

### Task 4: Calibrated input and persistent preferences

**Files:** Calibration sources; controller/input/UI; new focused calibration checks included by domain checker; independent audio-preferences path using existing graphics-settings path convention.

**Interfaces (namespace game):**
- `RhythmCalibration::begin()`, `tap(double audio_seconds)`, `finish() -> RhythmCalibrationResult`, `progress() const`. Result carries accepted flag, signed offset, jitter and diagnostic.
- `load_rhythm_calibration(const std::string&, double& offset, std::string&)` and `save_rhythm_calibration(const std::string&, double offset, std::string&)`; serialized milliseconds with finite +/-250 range.
- Controller adds `begin_calibration()`, `cancel_calibration()`, `set_calibration_offset(double seconds)`, `calibration_offset() const`. Game taps enqueue `raw_seconds - offset`; visuals/session update consume raw song time.

- [ ] Write checks: 24 taps at +80 ms yield +80 ms and corrected zero error, -60 ms stays negative, duplicates/count-in are excluded, isolated outliers rejected, high jitter/incomplete set rejected without replacing saved value. Non-object/malformed/out-of-range preferences preserve defaults. A calibration request invalidates in-flight song loads; completion/cancel restores selected song at zero. Establish RED.
- [ ] Implement pairing within +/-250 ms, unique expected pulses, four count-in and 24 measured pulses. Accept at least 20 inliers, median absolute deviation <=30 ms and absolute median <=250 ms; use 3*MAD with 15-ms minimum outlier threshold. Keep retry/cancel explicit and retain old value on rejection/save failure.
- [ ] Add calibration, cancel/retry, manual +/-250-ms slider and reset controls plus tap progress/result label. Persist separately from authored maps/graphics. Disable song/debug timing changes while calibration is active; song selection explicitly cancels it. Calibration uses metronome clock; taps never enter gameplay scoring.
- [ ] Run calibration/domain checks and debug build; exercise save/reload/reset, failed run, cancellation and loading interaction. Commit task slice and ledger evidence.
